# dsh-wiki

Плагин для DeepSeek Harness: вики-база знаний проекта, которую **плагин ведёт сам**
после выполнения задач. Папка вики — просто `wiki/` в корне рабочего пространства
(настраивается), чтобы не путаться с именем проекта и workspace.

## Что делает

1. **Правила в системном промпте.** Регистрирует секцию системного промпта с
   правилами вики — вместо блока «ведение вики» в глобальном `~/.dsh/AGENTS.md`.
2. **Инжект индекса в контекст.** При старте сессии проверяет, что `wiki/Home.md`
   существует (создаёт скелет, если нет), и вбрасывает индекс в контекст сессии.
   Никаких `@wiki-...`-импортов — в DSH их нет, плагин подгружает сам.
3. **Автоведение вики.** Когда задача (turn) завершена, плагин в фоне:
   - берёт список изменённых за задачу файлов и диффы из сервиса
     `workspaceChanges` (git-снапшоты + файловые инструменты);
   - вызывает модель (по умолчанию — ту же, на которой шла сессия) с ролью
     «хранитель вики»;
   - модель возвращает JSON: страница задачи + обновлённый `Home.md`;
   - плагин записывает файлы через `ctx.fs` (атомарно, с версионной защитой).

Страницы в Obsidian-совместимом markdown: перелинковка `[[...]]`,
«← [[Home]]» вверху, «## См. также» внизу, секретов в вики не кладём.

## Установка

Через Plugin Manager профиля или вручную:

```bash
dsh plugin --profile <профиль> add dsh-wiki
# desktop-профиль управляется через встроенную команду приложения
```

Либо в `package.json` профиля:

```json
{
  "dependencies": { "dsh-wiki": "github:mskproger/dsh-wiki" },
  "dsh": { "profile": { "bundles": ["...", "dsh-wiki"] } }
}
```

## Настройки

| Поле | По умолчанию | Описание |
|---|---|---|
| `wikiFolder` | `wiki` | Имя папки вики в корне workspace |
| `autoUpdate` | `true` | Автообновление вики после задач |
| `injectHome` | `true` | Вбрасывать `wiki/Home.md` в контекст сессий |
| `injectSubagents` | `false` | Инжектить Home.md и в сессии субагентов |
| `language` | `ru` | Язык страниц вики (`ru` / `en`) |
| `provider` | `''` | Провайдер модели-писателя; пусто = из сессии |
| `model` | `''` | Модель-писатель; пусто = из сессии |
| `maxTokens` | `8000` | Лимит токенов одного вызова писателя |
| `maxDiffBytes` | `12000` | Бюджет диффов в промпте писателя |
| `maxChangedFiles` | `30` | Сколько изменённых файлов учитывать |
| `delayMs` | `4000` | Пауза перед запуском писателя |
| `timeoutMs` | `180000` | Таймаут вызова писателя |
| `systemPromptOrder` | `20000` | Порядок секции системного промпта |
| `ignorePatterns` | см. ниже | Простые glob-паттерны игнорируемых файлов |

`ignorePatterns` по умолчанию: `wiki/**`, `**/wiki/**`, `*.log`, lock-файлы,
`.obsidian/**`, `.git/**`.

## Как это устроено

- Плагин — cordis-плагин с host-частью (`host/index.js`), как и другие
  DSH-плагины; настройки выводятся в UI через `Config` со `schemastery`.
- Точки интеграции: `agent/created` (инжект индекса), `agent/turn-stopping`
  (момент завершения задачи), сервисы `ctx.fs`, `ctx.llm`,
  `ctx.workspaceChanges`, `ctx.systemPrompt`.
- Автообновление не блокирует завершение задачи: работа идёт в фоне, по
  очереди на workspace; пока в workspace активен другой turn — писатель ждёт.
- Если изменения незначимы (логи, lock-файлы) — обновление пропускается.
